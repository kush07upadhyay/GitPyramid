# Contributor launch kit

Copy, edit and post. Everything here is written to be **true on the day you post it**, because the
[constitution](../../.specify/memory/constitution.md) says public claims must be true and checkable,
and because a project that overclaims loses its first contributors for good.

Search for the word `ADD` in capitals. Each one is a number or a link that only you can fill in, and
it must be correct when you post.

## 1. What you may say today, and what you may not

| You can say | You cannot say yet |
| :--- | :--- |
| It is an **open registry of open-source projects**, one small file per project, reviewed by pull request | That there is a 3D pyramid you can explore (it is designed, not built) |
| There are (ADD the number of bricks, 14 at first) bricks | That an AI recommends a tech stack (designed, not built) |
| A validator tells you exactly what to fix, with the file and line | Any number of users, stars or contributors you do not have |
| You can add a project in about 10 minutes, from the browser | That companies, GitHub or any project endorses or partners with you |
| The Pyramid Score is written, tested and public | That the project is "the best", "the first" or "the largest" of anything |
| Sponsors can fund the stairs but never change what is listed or how it ranks | That the name is cleared (it is not until you hear back, see [NEXT_STEPS](../NEXT_STEPS.md)) |

**Before you write "10 minutes", have one friend time it.** Give them only the README. If it took
them 25 minutes, write "under half an hour". Then fix what slowed them down.

**Be open that AI tools helped build this.** It is true, it is the norm now, and contributors find
out anyway. One sentence is enough: "I built the foundation with AI assistance (GitHub Copilot) and I
review everything. The project has a clear AI policy for contributions." It is also what the project
asks of everyone else.

## 2. The pitch

One sentence:

> GitPyramid is an open registry of the open-source projects developers need, and anyone can add one
> in about 10 minutes.

Three lines:

> Every project is a "brick" in one small file, checked by CI and reviewed by people. A 3D pyramid
> to explore them is coming. Right now the most useful thing you can do is add or review a brick.

### Where not to post

Do not post in a community that bans self-promotion, and do not post the same text in many places on
the same day. Do not post on Hacker News or a "show" board until the 3D monument exists, because those
communities expect something to try. Do not tag companies or maintainers of listed projects. It can
look like an endorsement claim.

## 4. What a welcome looks like

### A pinned Discussions post (Announcements)

```text
Welcome to GitPyramid.

This is an open registry of open-source projects. Right now there are three ways to help:

1. Add a project. It takes about (ADD MINUTES) minutes: CONTRIBUTING.md, "Add a brick in 10 minutes".
2. Review an open brick pull request. Check one fact against the repository and say what you found.
3. Pick an issue labeled "good first issue".

Stuck? Ask here. If a message from CI confused you, tell us, because that is a bug in our message.

We read everything. Expect a reply within 48 hours.
```

### First reply on a first pull request

```text
Thank you for your first contribution to GitPyramid. CI is running. If something needs fixing, the
message names the file and line and says what to do. When it is green, please review the open brick
pull requests listed in the review rule, with one specific finding each. Then a maintainer will merge.
```

### Closing a generated, unverified submission, kindly

```text
Thank you for the pull request. We are closing it because it looks generated and we could not tell
that the facts were checked against the repository. That is our rule for everyone, written down in
docs/decisions/0007-review-rule-and-ai-policy.md. AI help is welcome when you verify each claim and
write the sentence yourself. If you do that, please open a new one. We would be glad to see it.
```

## 5. Answers to likely questions

| Question | Honest answer |
| :--- | :--- |
| Is this affiliated with GitHub? | No. It is independent. The README says so. |
| Is the name allowed? | (ADD YOUR TRUTHFUL ANSWER. If you have not heard back: "I have asked the Git project's trademark holders and I will rename if they ask.") |
| How is this different from an awesome list? | Awesome lists are great and we respect them. Here each project is a validated file, scores are computed from live GitHub data instead of written by hand, and the registry feeds a visual monument and recommendations that are planned. |
| Can I add my own project? | Yes. Say so in the pull request. Another person has to approve it. |
| Can a company pay to be listed or ranked higher? | No, and it is a rule in the constitution. Sponsors can fund the Grand Stairways, labeled as sponsors, and never change what is listed or how it ranks. |
| Who can rate a project's impact? | Only maintainers, with a public rubric, so nobody rates their own project. |
| What license is it? | Code and docs are MIT. The registry data is CC0. Sponsor logos stay with their owners. |
| Did you use AI? | Yes, to scaffold the foundation, and it is reviewed. Contributions follow the AI policy. |
| When is the 3D version? | It is designed in the specs and comes after the registry, see the roadmap. I do not give dates I cannot keep. |

| 7 | A short recap with honest numbers, what is next and what you need. |

## 7. Do not

- Do not buy stars, followers or contributors. The Pyramid Score exists because fake stars are
  common, and a project built on that would be a joke.
- Do not promise a date, a feature or a sponsor you do not have.
- Do not paste a token, a private email or a screenshot with personal details anywhere.
- Do not reply defensively to criticism. Thank the person, check whether they are right, and say what
  you will do.
